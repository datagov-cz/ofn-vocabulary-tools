Quick start

  1. Create a package with stereotype slovnikyPackage.
  2. Place every consumed element and relationship below it, directly or in nested packages.
  3. Apply one of the exact supported stereotypes listed below.
  4. Fill all remaining metadata using the exact tagged-value names from the exhaustive tables.
  5. Export UML XMI 2.1 with profiles, stereotypes, tagged values, and relationships, then upload the .xml or .xmi file.
Same input control: Archi XML and EA XMI are detected automatically.

How EA tagged values are read

Canonical names

Every non-type property is read from the stereotype application's tagged values. The tables in this guide give the canonical EA tag name, for example klíčové slovo or podmínky užití - autorské dílo. The parser also tolerates differences in case, separators, and diacritics introduced by a profile exporter, but canonical names are recommended.

Single values and lists

  • For single-valued fields, the first value is used.
  • List fields split one value on semicolons and trim whitespace.
  • Invalid URLs, dates, emails, code-list values, and media types are omitted with a warning according to each table's allowed-value rule.

Names and package boundary

The UML element name is used as the Czech name. A dataset without it is skipped. Only base UML elements and relationships below a package stereotyped slovnikyPackage are read, including descendants in nested packages.

Exception for typ: a typ tagged value is ignored. Type always comes from the element or relationship stereotype.

How to create model relationships

Dataset and distribution

Create a packaged UML relationship between the datovaSada element and a distribution element. Direction and UML relationship type are not checked for this link.

Dataset and terms

The metoda sbírání pojmů dataset tag accepts podrobně, standard, or agresivně. Detailed uses directly associated terms; standard adds properties composed into selected classes and eligible named associations; aggressive traverses directed named associations, Generalization/Specialization, and Composition recursively.

The UML relationship object itself must also be below slovnikyPackage. A relationship outside the package is ignored even when both endpoints are included.

Minimal relevant EA XMI

<xmi:XMI xmlns:xmi="http://schema.omg.org/spec/XMI/2.1"
 xmlns:uml="http://schema.omg.org/spec/UML/2.1" xmlns:Slovniky="urn:Slovniky">
 <uml:Model xmi:id="model">
  <packagedElement xmi:type="uml:Package" xmi:id="pkg" name="Doprava">
   <packagedElement xmi:type="uml:Class" xmi:id="ds" name="Jízdní řády"/>
  </packagedElement>
 </uml:Model>
 <Slovniky:slovnikyPackage base_Package="pkg"/>
 <Slovniky:datovaSada base_Class="ds">
  <tag name="popis" value="Aktuální jízdní řády."/>
  <tag name="klíčové slovo" value="doprava;jízdní řád"/>
  <tag name="vstupní stránka" value="https://data.example.cz"/>
 </Slovniky:datovaSada>
</xmi:XMI>

Pre-export checklist

  • XMI 2.1 contains the UML model and profile applications.
  • Every consumed element and relationship is below slovnikyPackage.
  • Dataset and distribution stereotypes use the exact canonical names.
  • Every non-type property uses a tagged value listed in this guide.
  • Every dataset has a UML name and every distribution is related to its dataset.
  • Values satisfy the allowed formats in the tables.

Known limitations

  • UML name is interpreted as Czech because XMI names have no language marker.
  • Only elements and relationship forms used by the shared dataset mapping are emitted.
  • Unknown stereotype tags are preserved by the parser but ignored by JSON-LD generation.
