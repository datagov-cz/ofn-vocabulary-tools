Rychlý postup

  1. Vytvořte balíček se stereotypem slovnikyPackage.
  2. Všechny zpracovávané prvky a vztahy umístěte pod něj, přímo nebo ve vnořených balíčcích.
  3. Použijte některý z přesných podporovaných stereotypů uvedených níže.
  4. Ostatní metadata vyplňte přesnými názvy tagged values z vyčerpávajících tabulek.
  5. Exportujte UML XMI 2.1 včetně profilů, stereotypů, tagged values a vztahů a nahrajte soubor .xml nebo .xmi.
Stejný vstup: Archi XML a EA XMI se rozpoznají automaticky.

Jak se čtou tagged values EA

Kanonické názvy

Každá vlastnost kromě typu se čte z tagged values aplikace stereotypu. Tabulky uvádějí kanonický název tagu EA, například klíčové slovo nebo podmínky užití - autorské dílo. Parser toleruje i rozdíly ve velikosti písmen, oddělovačích a diakritice zavedené exportérem profilu, doporučené jsou však kanonické názvy.

Jednotlivé hodnoty a seznamy

  • U polí s jedinou hodnotou se použije první hodnota.
  • Seznamová pole dělí jednu hodnotu podle středníků a odstraňují okolní mezery.
  • Neplatná URL, data, e-maily, číselníkové hodnoty a typy médií se vynechají s varováním podle pravidla povolených hodnot v tabulce.

Názvy a hranice balíčku

UML name se použije jako český název. Datová sada bez něj se přeskočí. Čtou se pouze základní UML prvky a vztahy pod balíčkem se stereotypem slovnikyPackage, včetně potomků ve vnořených balíčcích.

Výjimka typ: tagged value typ se ignoruje. Typ vždy pochází ze stereotypu prvku nebo vztahu.

Element datové sady

Jeden soubor JSON-LD se vytvoří pro každý zahrnutý UML prvek se stereotypem datovaSada. UML name poskytuje povinný český název, název výstupního souboru a generované IRI datové sady.

Jak vytvořit vztahy v modelu

Datová sada a distribuce

Vytvořte zabalený UML vztah mezi prvkem datovaSada a prvkem distribuce. Směr ani UML typ tohoto propojení se nekontroluje.

Datová sada a pojmy

Tag datové sady metoda sbírání pojmů přijímá podrobně, standard nebo agresivně. Podrobná strategie použije přímo asociované pojmy; standard přidá vlastnosti v kompozici vybraných tříd a způsobilé pojmenované asociace; agresivní strategie rekurzivně prochází orientované pojmenované asociace, Generalization/Specialization a Composition.

Samotný objekt UML vztahu musí být rovněž pod slovnikyPackage. Vztah mimo balíček se ignoruje, i když jsou zahrnuty oba koncové body.

Minimální relevantní EA XMI

<xmi:XMI xmlns:xmi="http://schema.omg.org/spec/XMI/2.1"
 xmlns:uml="http://schema.omg.org/spec/UML/2.1" xmlns:Slovniky="urn:Slovniky">
 <uml:Model xmi:id="model">
  <packagedElement xmi:type="uml:Package" xmi:id="pkg" name="Doprava">
   <packagedElement xmi:type="uml:Class" xmi:id="ds" name="Jízdní řády"/>
  </packagedElement>
 </uml:Model>
 <Slovniky:slovnikyPackage base_Package="pkg"/>
 <Slovniky:datovaSada base_Class="ds">
  <tag name="popis" value="Aktuální jízdní řády."/>
  <tag name="klíčové slovo" value="doprava;jízdní řád"/>
  <tag name="vstupní stránka" value="https://data.example.cz"/>
 </Slovniky:datovaSada>
</xmi:XMI>

Kontrolní seznam před exportem

  • XMI 2.1 obsahuje UML model a aplikace profilu.
  • Každý zpracovávaný prvek a vztah je pod slovnikyPackage.
  • Stereotypy datových sad a distribucí používají přesné kanonické názvy.
  • Každá vlastnost kromě typu používá tagged value uvedenou v tomto průvodci.
  • Každá datová sada má UML name a každá distribuce má vztah ke své datové sadě.
  • Hodnoty splňují povolené formáty v tabulkách.

Známá omezení

  • UML name se považuje za český, protože názvy XMI nemají značku jazyka.
  • Vypisují se pouze prvky a formy vztahů používané společným mapováním datových sad.
  • Neznámé tagy stereotypu parser zachová, ale generování JSON-LD je ignoruje.
