ArchiMate XML → JSON-LD

How to prepare the source ArchiMate model

A practical guide to the elements, relationships, property names, and value formats expected by create_jsonld_files in jsonld_creation.py.

Quick start

  1. Create property definitions using the exact source names shown in the tables below.
  2. Create a dataset element, give it a Czech name, and add a typ property whose value contains datová sada.
  3. Fill in the dataset properties, respecting the documented prefixes, formats, and capitalization.
  4. Create a separate element for every distribution, set its exact subtype in typ, and connect it to the dataset with a relationship.
  5. Related distributions are included automatically when they are connected to the dataset.
Input versus output: ArchiMate source property names use spaces, for example kontaktní bod - email. JSON-LD keys keep their underscored form, for example kontaktní_bod.

How the converter reads ArchiMate XML

Property names must match exactly

An element refers to an entry in propertyDefinitions through propertyDefinitionRef. The converter uses the text of the definition's first <name> as the resolved property key. If the definition has no name, its identifier is used. Source names are case-sensitive and diacritic-sensitive, and they must use spaces instead of underscores. The expected source name is soubor ke stažení, not soubor_ke_stažení. This transformation applies only to input lookup; generated JSON-LD keys retain underscores. 

<propertyDefinitions>
  <propertyDefinition identifier="prop-popis" type="string">
    <name xml:lang="cs">popis</name>
  </propertyDefinition>
</propertyDefinitions>

<element identifier="dataset-1" xsi:type="BusinessObject">
  <properties>
    <property propertyDefinitionRef="prop-popis">
      <value xml:lang="cs">Dataset description</value>
    </property>
  </properties>
</element>

Single values, repeated values, and semicolons

  • For single-valued fields, the converter uses the first value.
  • For fields described as lists, a single value is split on semicolons, for example témata:doprava;témata:regiony.
  • If the same property occurs multiple times in XML, the parser creates a list; those already separate values are not split again on semicolons.
  • Empty list items are discarded and surrounding whitespace is removed.

Languages and nested properties

A dataset needs a Czech name using <name xml:lang="cs">…</name>. Without one, the element is skipped. If several Czech names exist, the first is used for the IRI and file name. All names are written under their xml:lang keys in název.

Nested source properties use the name of their output object as a prefix, separated from the child name by - . For example, use podmínky užití - autorské dílo, not autorské dílo.

Dataset element

A JSON-LD file is created for every element whose typ property contains datová sada. This comparison is case-insensitive and allows a partial match. The element's concrete ArchiMate xsi:type is not checked.

The IRI is generated as https://slovník.gov.cz/{sanitized-Czech-name}. The Czech name is trimmed, lowercased, and characters disallowed in the local IRI part are replaced with hyphens. It also becomes the basis of the .jsonld file name. JSON-LD typ is always ["Datová sada", "Datová sada SSP"].

Distribution element

An element is a distribution candidate when its typ contains distribuce. To be emitted, it must be connected to a dataset and its typ must contain one of the exact subtypes below. Matching is case-insensitive; the element's xsi:type is ignored.

Allowed subtypes: distribuce - soubor ke stažení or distribuce - datová služba. A generic distribuce value is insufficient and causes the element to be skipped with a warning.

The distribution IRI is {dataset IRI}/distribuce/{index}, with a zero-based index determined by model element order. Its output type is always ["Datové rozhraní", "Distribuce"], and its names are copied from the distribution.

How to create model relationships

Dataset → distribution

A dataset and distribution must be connected by an entry in relationships. Direction and relationship type are not checked for distributions: the dataset may be either source or target. Found distributions are included automatically. 

<relationships>
  <relationship identifier="rel-1" xsi:type="Association"
                source="dataset-1" target="distribution-1" />
</relationships>

Dataset → related term

Related-term lookup accepts only a relationship whose normalized xsi:type is exactly Association. Direction is irrelevant. The connected element's typ must contain typ subjektu or typ objektu. Found terms are included automatically.

Minimal example of relevant XML

This example deliberately shortens the property-definition list. A real file needs one propertyDefinition for every source property name used. 

<model xmlns="http://www.opengroup.org/xsd/archimate/3.0/"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       identifier="model-1">
  <propertyDefinitions>
    <propertyDefinition identifier="pd-typ" type="string">
      <name xml:lang="cs">typ</name>
    </propertyDefinition>
    <propertyDefinition identifier="pd-popis" type="string">
      <name xml:lang="cs">popis</name>
    </propertyDefinition>
    <propertyDefinition identifier="pd-distribuce" type="string">
      <name xml:lang="cs">distribuce</name>
    </propertyDefinition>
    <propertyDefinition identifier="pd-url" type="string">
      <name xml:lang="cs">přístupové url</name>
    </propertyDefinition>
  </propertyDefinitions>

  <elements>
    <element identifier="dataset-1" xsi:type="BusinessObject">
      <name xml:lang="cs">Dopravní data</name>
      <name xml:lang="en">Transport data</name>
      <properties>
        <property propertyDefinitionRef="pd-typ">
          <value>datová sada</value>
        </property>
        <property propertyDefinitionRef="pd-popis">
          <value>Přehled dopravních dat.</value>
        </property>
        <property propertyDefinitionRef="pd-distribuce">
          <value>ano</value>
        </property>
      </properties>
    </element>

    <element identifier="distribution-1" xsi:type="Artifact">
      <name xml:lang="cs">CSV distribuce</name>
      <properties>
        <property propertyDefinitionRef="pd-typ">
          <value>distribuce - soubor ke stažení</value>
        </property>
        <property propertyDefinitionRef="pd-url">
          <value>https://data.example.cz/doprava.csv</value>
        </property>
      </properties>
    </element>
  </elements>

  <relationships>
    <relationship identifier="rel-1" xsi:type="Association"
                  source="dataset-1" target="distribution-1" />
  </relationships>
</model>

Pre-export checklist

  • The XML root is model and uses a valid ArchiMate structure.
  • Every used property definition has the exact source key from these tables as its first name.
  • Every dataset and distribution candidate has a typ property.
  • Each dataset has a Czech name and a typ containing datová sada.
  • The prefixes ovm:, témata:, frekvence:, euroVoc:, isvs:, formáty:, and mediaTypes: use the exact capitalization.
  • URLs begin with https://; http:// values are discarded.
  • Dates use YYYY-MM-DD, and email addresses contain no whitespace.
  • Lists within one value use semicolons, not commas.
  • Every nested source property uses its object name followed by - as a prefix.
  • Distributions have an exact subtype and a relationship to their dataset.
A value that fails its regular expression is omitted and produces a warning. For lists, only invalid items are discarded; valid items remain.

Known limitations of the current implementation

  • Constants exist for sdílí_údaj, odpovídající_pojem, způsob_získání_sdílených_údajů, způsob_sdílení_údajů, and typ_obsahu_sdílených_údajů, but create_jsonld_files does not export them.
  • Missing required values are logged with their full field paths. If external validation is enabled, the generated document is also rejected by JSON Schema validation.
  • The JSON-LD context is hard-coded. This guide describes the current implementation, not the behavior of every DCAT-AP-CZ version.
